# Casdoor 服务级连接实施补充

状态：实施中，用户已要求继续完成服务级连接及后续目录功能。依据 PRD V2 和现场管理连接认证核查，不新增实例级授权规则。

1. 验证 OAuth client_credentials：后端获取、缓存、到期重取、并发协调、密钥不回传和不跟随重定向。
2. 独立服务、管理凭证、组织及服务范围数据模型；追加当前版本幂等迁移。原 Connection 保留为历史配置或内部组织快照上下文，不再作为页面服务行。
3. 服务创建/编辑、认证测试、发现组织和按组织同步；每个新接口验证服务权限、组织归属和动作权限。
4. 页面采用服务及组织选择器，目录分页查询不得依赖业务 Owner 筛选。旧配置通过显式选择映射到新服务，保留原快照 ID。
5. 更新五个页面的接口、中文及英文文案；区分认证、发现、同步及原生产品规则。
6. 后端/迁移/前端测试、构建、服务实际启动测试、隔离及生产只读验证。
7. 部署时备份；逐页验证服务、组织、应用和用户，记录未交付的原生管理操作。不得将读取功能标为所有管理写入已完成。

本阶段不静默创建生产全局身份。用户此前提供的 app-built-in 凭证只用来验证协议，不自动成为 Mayfly 专属身份。配置可由管理员填入其明确选择的管理身份；需要自动登记专用管理应用时先展示具体配置及影响。

## 页面及接口修订（本阶段覆盖旧 P1 连接模型）

- 连接管理主表每行是一套服务，展示根地址、管理 Client ID、身份状态、最近验证时间和已发现组织数。表单不再固定组织或应用 Owner；密钥仅在输入时出现，编辑留空保留。
- 测试使用真实管理身份验证和组织发现，不保存；保存时再次验证后将服务、加密凭证、组织上下文一起事务提交。普通业务组织应用凭证不能登记为全局管理身份。
- 历史应用集成配置单独展示，通过显式迁移保留旧组织快照的主键。不会自动复用旧业务密钥作为服务管理身份，也不会自动扩大旧账号范围。
- 应用、用户、授权依据及操作记录采用统一服务/组织选择器。查询和同步 URL 同时携带 serviceId/organizationId；服务端校验归属，不接受调用者传内部历史连接 ID 绕过校验。
- 组织选择器可展开五类目录的最近尝试、最近成功、成功记录数及失败/过期状态。旧快照在失败时保留，页面不能把它显示为新采集成功。
- 自动采集每分钟检查到期任务，按服务配置周期发现组织及同步各组织；手动采集即时执行。服务配置使用凭证版本比较，拒绝并发编辑覆盖新密钥或旧认证结果覆盖新验证。
- 现阶段新接口为 `/api/casdoor/services`、`/services/test`、`/services/:serviceId/discover`、`/services/:serviceId/organizations`、`/services/:serviceId/organizations/:organizationId/{sync,applications,users,objects,operations}`；沿用现有 Mayfly 动作权限。登记/修改全局身份仅管理员可操作，服务数据权限单独校验。
