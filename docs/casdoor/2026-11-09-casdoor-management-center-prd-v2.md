## 1. 背景与问题

Mayfly 用于集中管理 Casdoor 后端中的组织目录、用户和应用访问权限。Octop 是使用 Casdoor 认证的业务系统之一，不能成为 Casdoor 模块的上级对象。

当前实现将服务地址、单个组织、应用 Client ID / Secret 和应用 Owner 筛选组合为一行“连接”。现场历史记录 `casdoor-octop-8090` 即采用这种结构。它表达的是一条带有应用认证身份及目录筛选的集成配置，不能仅凭名称和服务地址就认定为整套 Casdoor 后端的管理连接。

这会产生以下错误：

- 管理员容易认为必须为每个业务应用新建一条后端连接。
- 应用身份、组织归属及查询 Owner 被混为同一个范围条件。
- 用某个应用凭证认证成功，被错误解释为获得整个 Casdoor 后端管理权。
- 同一组织的用户可能随不同应用凭证重复采集和显示。
- 旧配置显示“同步成功、应用 0 条”时，无法区分真实空目录、错误筛选与权限受限。

## 2. 产品目标与边界

一条服务连接登记一套独立的 Casdoor 后端。Mayfly 使用专属于它的全局管理身份长期管理该后端的全部组织，包括内置管理组织；组织、应用、用户的关系及操作规则遵循 Casdoor 本身。Mayfly 不额外建立业务组织启用名单或实例访问授权模型。具体调用仍受 Casdoor 原生规则校验。

本期包含：

- 服务连接、管理凭证和可管理组织的独立配置。
- 组织发现、组织选择、按组织的完整目录同步和分项状态。
- 应用及用户的列表、详情、本期允许字段编辑；用户启停和有可靠激活路径的新建用户。
- 角色、群组、权限读取；在已验证的 Casdoor 授权语义下管理受管应用的用户访问。
- 变更预览、幂等执行、回读验证、结果核对、操作审计。
- 原有数据、身份映射、业务资源引用的无损迁移。
- Octop 等业务资源的可选关联，不以登记业务实例作为 Casdoor 管理前提。

本期不包含：新建或删除组织、新建或删除应用、删除用户、密码重置、群组成员写入、任意 Casbin 模型编辑、跨组织共享应用授权、业务会话即时注销及中央任务层编排。中央任务层后续复用本模块的已授权服务接口。

## 3. 正确的领域定义

### 3.1 Casdoor 服务

服务是一个可独立识别的 Casdoor 后端部署，其管理入口例如 `http://192.168.102.247:8000`。服务连接的主体是该部署，不是某个应用、组织、SSH 主机或 Octop 实例。

服务连接保存：服务标识、显示名称、管理 API 根地址、TLS 设置、连接超时、服务探测状态和组织发现状态。认证材料由独立凭证对象保存。组织筛选不再是服务身份的一部分。

同一个后端默认展示一行服务连接。仅更换凭证或增加组织不新建服务行。相同地址是重复检测线索，反向代理别名、同址替换后端或多个独立部署不得仅按 URL 自动合并。

### 3.2 组织

组织是用户与应用的业务归属范围。组织引用必须由“服务标识 + Casdoor 真实组织标识”确定。同名组织位于不同 Casdoor 服务时是不同对象。

组织保存来源标识、名称、显示名、最近确认时间、目录状态及来源服务。组织列表来自 Casdoor，不新增本地启用字段来改变它的业务归属。不能使用应用名称、应用 Owner 或 Client ID 生成组织身份。

### 3.3 用户

用户属于组织。服务、组织和源稳定 ID 共同确定本地用户身份；API 所需的 owner/name 单独保存。邮箱、用户名和显示名仅用于搜索，不能跨组织自动合并用户。

组织用户同步一份。用户可以按 Casdoor 实际规则访问本组织的一个或多个应用，不因为登录多个应用而复制用户。

### 3.4 应用

应用属于组织，拥有自己的 Client ID、Client Secret 和认证设置。应用快照保存服务、组织、真实应用对象 owner/name、Client ID 及允许显示的配置；不向列表、详情或导出返回 Client Secret。

Casdoor 应用对象的 `owner` 与 `organization` 必须分开保存。现场接口使用 `organization` 表达应用所属组织；对象 Owner 不能被当作业务组织，也不能填写为 `octop` 之类的应用类型来限制组织应用目录。

### 3.5 管理凭证

凭证是调用 Casdoor API 使用的认证身份，不是目录父节点。凭证归属、请求执行身份与可操作范围分别记录。应用凭证仍属于其源应用，即使该认证方式允许调用组织管理 API，也不改变其他应用和用户的归属。

管理身份必须经现场协议核查，具备管理整套服务的范围；Mayfly 现有账号与动作权限仍控制谁可以调用管理功能，但不另造 Casdoor 的组织归属或业务访问限制。认证成功不等于组织发现成功，更不等于任意操作可以绕过 Casdoor 原生规则。

### 3.6 业务资源关联

Octop 实例是业务运维模块的资源，可关联 Casdoor 中对应的应用。关联保存应用引用与业务资源引用，不通过共享 Client ID / Secret 表达多个组件的关系。

一个 Casdoor 应用代表一个业务系统，同一业务系统可以有多个 Octop 部署实例。不得增加“一应用最多一个部署实例”的限制，也不得据此引入新的实例级访问授权规则。业务部署不是新增的 Casdoor 原生对象层级；需要登记关联时由可选业务适配器保存，不改变 Casdoor 应用、用户和凭证的定义。

未注册业务适配器时，组织、用户、应用及授权管理仍可独立运行。

## 4. 服务与组织的管理上下文

导航层级为：Casdoor 服务 → 当前组织 → 用户、应用、授权、操作记录。

连接管理显示可见服务列表。其他页面同时选择服务和组织，不再将 `connectionId` 同时用作服务身份、组织身份和认证应用身份。

组织选择器来自专用管理身份通过 Casdoor 原生接口读取的组织列表，包含内置组织；不增加本地业务组织启用流程。无法列举组织或仅具备组织级范围时报告“全服务管理连接验证未通过”，不能把手动输入单个组织作为完整连接的替代验收。

发现被拒绝不表示服务没有组织。能够发现组织也不证明所有管理动作都可执行，必须按现场原生 API 分别验证。组织列表刷新后应反映 Casdoor 中新增的组织，不要求再做 Mayfly 组织启用审批。

切换服务或组织后清空应用、用户、勾选、分页和未提交预览；旧请求晚返回不能覆盖新上下文。无权访问指定上下文时明确拒绝，不能自动换到其他组织。

## 5. 管理认证要求

### 5.1 本期认证方式

服务连接表单先选择“管理 API 认证方式”，不再无条件要求业务应用 Client ID / Secret。

本期采用已通过同镜像隔离验证的 Casdoor 机器身份机制：由 Casdoor 管理员登记专供 Mayfly 使用、归属 `built-in` 的管理应用，配置 `client_credentials`。Mayfly 后端使用该管理应用的 Client ID / Secret 向令牌端点换取 AccessToken，再用 `Authorization: Bearer` 调用管理 API。令牌依据实际有效期缓存并重新获取，不要求人员定期粘贴令牌，不依赖个人管理员长期登录。生产管理身份的登记由管理员明确执行，不通过迁移或后台任务静默创建。

Client ID / Secret 仍归属于这个专用管理应用，用来认证 Mayfly 的机器身份；它不代表业务目录的父节点。服务连接的一行仍代表 Casdoor 后端，不按这个应用或各 Octop 业务应用创建多条服务连接。不能将 `smartcore` 中的旧 Octop 应用凭证直接认定为具有全服务管理能力。Basic 认证可用于协议验证，线上管理调用优先使用后端自动取得的 Bearer 令牌。

Access Key / Secret 是后续候选方式。现场 Swagger 没列出完整相关定义，不足以证明支持或不支持；需通过该部署的认证实现和隔离测试核实其范围、传输及轮换行为后才能启用，首期不显示可用占位项。

### 5.2 保存和轮换

- 本期每套服务使用一个专用全局管理身份覆盖全部组织，身份和服务的数据对象仍分离，支持受控轮换。无需按组织配置多套身份或逐组织启用写权限。
- 轮换或更新身份时不复制组织、用户或应用快照，不静默切换至其他身份补偿失败。
- 凭证轮换保留服务、组织和源对象身份，但使对应读取探测、写入准入及未提交预览失效，重新验证后才允许使用。
- 已登记服务的目标地址默认只读；地址迁移通过专用变更验证流程处理。同址后端被替换也须重新确认服务身份，不能沿用旧授权结果。
- 密钥和令牌不得写入 URL、前端存储、审计明文或错误输出；跨目标重定向不得转发认证信息。
- 凭证过期或被拒绝时保留旧快照并标明状态，停止相关写入，不自动换身份或重发命令。

## 6. 页面需求

保留五个主入口，不增加 Octop 专用的 Casdoor 首页。

### 6.1 连接管理

每行代表一套 Casdoor 服务。列为服务名称、管理地址、认证身份摘要、已发现组织数量、连接状态、最近验证时间和操作。数量未取得时显示“未核实”，不显示零。

新建表单包含服务名称、API 根地址、超时、TLS，以及专用管理身份认证配置。管理身份区域明确显示来源组织 `built-in`、管理应用标识和 Client ID / Secret，解释其用途为后端换取机器令牌。服务主体不要求绑定任何 Octop 业务应用；认证后发现组织，组织发现失败则连接保持未通过验证。

详情分为服务、管理身份、源组织列表、能力状态。操作包括测试认证、发现组织、轮换凭证和查看同步结果。首期不提供服务删除；停用服务采集时保留数据和审计。

历史配置 `casdoor-octop-8090` 不直接作为正式服务行继续展示；迁移待确认期间进入“历史集成配置”区域，清楚标识来源、原组织及凭证类型。

### 6.2 应用管理

顶部为服务和组织选择器。列表默认查询当前组织全部可读应用，支持关键词、登录状态、源存在性及受管状态筛选与分页。服务连接不提供应用 Owner 筛选；诊断工具保留真实对象 Owner，但诊断查询不能提交为组织完整目录。

详情展示 owner/name、所属组织、Client ID、首页、回调地址、登录设置、同步及授权依据。允许编辑显示名、首页、回调地址和登录开关，具体动作按现场协议逐项启用；Client ID、Secret、owner/name 和组织不在本期编辑范围。

业务资源关联为可选动作，不决定应用是否可见或是否能管理。关联失败不阻断 Casdoor 自身授权操作。

### 6.3 用户管理

按服务和组织列出用户，支持关键词、账号状态和源存在性筛选、分页及详情。新建仅在已验证激活或外部认证路径时启用；编辑仅限显示名和邮箱。组织账号启停单独授权，并显示对该组织所有应用的影响。

全局管理身份也必须保留 Casdoor 原生保护。现场同镜像隔离验证中，`built-in` 默认禁止新增用户，但可以修改已有内置用户的显示名；Mayfly 不能为实现“用户管理”而自动关闭该保护，也不能把这类原生拒绝判为服务连接失效。

用户详情提供应用访问视图，分别显示受管角色成员、策略判定和已核实依据，不将组织用户总数当作某个应用可登录人数。

### 6.4 访问授权

先选择服务、组织及本组织应用，再显示用户访问、角色、群组和权限。所选用户必须来自相同服务和组织；本期不支持跨组织共享应用授权。

初始化、授予、撤销沿用原需求，但须先验证现场 Casdoor 的默认登录规则、模型、资源、动作、效果和例外语义。组织归属是必要关联条件，不自动等同于某个应用的显式授权；也不能假设所有应用默认禁止未入选用户。

外部已有角色与权限只读展示。只有明确登记且无漂移的受管对象允许修改；无法可靠解释现有策略时仅开放只读并给出原因，不能通过删除原权限或创建通用拒绝规则强行接管。

单次最多 100 个显式用户，换页、换筛选或换应用清空勾选。撤销只撤销本系统维护的授权；外部规则和业务会话独立说明。策略结果仅为 allowed/denied/unknown，不承诺完整登录或会话结果。

### 6.5 操作记录

按服务、组织、时间、动作、状态、操作者及目标筛选；默认仅列已提交操作。跨组织汇总只有具备各组织审计权限时开放，并在每行标明来源，不混合为一个组织的数据。

详情保留脱敏差异、源对象标识、管理身份引用、执行步骤、回读结果、权限上下文、时间及会话影响。只读审计权限不能触发重新核对或写入，不提供清空审计。

## 7. 同步与数据正确性

同步单位为“服务 + 组织 + 对象类别”，类别包括用户、应用、角色、群组和权限。一个凭证覆盖多个组织时分别采集、分别提交，某组织失败不清空其他组织或类别。

组织发现与组织目录同步分别显示状态。每一类均保存最近尝试、最近成功、数量、错误原因及所用管理身份。状态为未同步、同步中、成功、失败、使用上次成功数据；认证状态、组织可见性和写能力另行表达。

完整分页读取并验证范围后，按类别原子提交。分页中断、重复页、权限受限或查询完整性无法证明时保留旧快照，不将未返回对象标为删除。远端返回列表只包含已核实的组织时才能作完整组织快照；空列表本身不是完整性证明。

对象唯一键以服务和源组织/对象稳定标识为基础，不含凭证 ID。凭证轮换、名称更改和新增管理身份不得导致用户或应用重复。应用真实 owner/name、用户 UUID 和 API owner/name 分别保存。

调度器每 60 秒检查到期范围，默认周期 3600 秒、最小 60 秒。同步和写操作共享同一服务/组织锁；写操作额外校验目标源指纹，不能依赖本地锁阻止 Casdoor 外部修改。自动同步只读远端，不自动修改组织、初始化权限或创建用户。

## 8. 权限与远端变更流程

Mayfly 系统管理员可登记服务和管理本地范围，但不因此自动成为 Casdoor 全局管理员。Casdoor 真实权限由远端身份决定。

保留 Mayfly 现有管理入口及动作权限，所有调用必须校验当前操作者。组织、用户和应用的归属及可执行操作遵循 Casdoor，不能另加产品未要求的本地组织白名单或实例授权规则。将历史组织级连接替换为全局管理身份时，不能顺带把所有旧普通操作者升级为全服务管理员；现有账号权限如何映射须在实施计划中明确并验收。nil 调用上下文不得绕过公开接口检查。

远端写入统一采用编辑 → 预览 → 确认执行 → 回读 → 操作结果。预览只读，绑定操作者、服务、组织、管理身份版本、目标、源指纹和有效期，默认 5 分钟。用户资料与启停目标恰好一个，应用编辑目标恰好一个，授予/撤销为 1–100 个显式用户；初始化可为 0–100 个用户，但空白名单影响须突出展示。

执行只接收 previewId 与幂等键，服务端恢复规范命令，再验证范围、动作和源状态。不能通过客户端新增组织 ID 或替换目标跨范围执行。凭证或目标身份变化时旧预览失效。

HTTP 200 的业务错误不能当成功。超时、连接中断或可能在写入后发生的服务器错误标为 unknown；不盲目重试。结果归并沿用 pending/verified/noop/failed/unknown，部分成功保留已完成分项，不宣称回滚。核对操作只读回源，不补发写请求；已知失败修正后重新预览。

按动作分别展示协议支持、读取验证和写权限状态。读取成功不自动启用写入；协议经同版本隔离验证且读取条件满足后，管理员可显式启用对应动作，生产写权限尚未实测时如实提示。首次正式写入若被拒绝，则记录失败、关闭相关写准入并要求重新验证，不通过生产写探针建立权限。

## 9. 与现场 API 的对应原则

2026-11-09 只读检查现场 Swagger 得到：

- `GET /api/get-organizations?owner=...`：组织列表；参数中的 owner 是源端对象 Owner，不是应用筛选。
- `GET /api/get-organization?id=...`：单个组织详情。
- `GET /api/get-organization-applications?organization=...`：组织应用列表；不得增加业务类型 Owner 作为默认范围。
- `GET /api/get-applications?owner=...`：按源端 Owner 查询应用；如用它辅助管理目录，必须依据真实 organization 过滤并验证完整性。
- `GET /api/get-users?owner=组织名`：组织用户目录。owner 的语义不能直接套用于应用对象。
- Swagger 声明 `Authorization` 请求头的 AccessToken 认证定义；定义存在不证明所有接口对任意令牌开放。

组织可见性、分页、错误信封及权限仍按现场实际响应验证。Swagger 的参数或返回 schema 不完整时，以同版本隔离行为及已核实实现补充，不把本地源码提交等同于部署镜像版本。

应用更新已有有限隔离证据：仅更新显示名时，附带原应用名称、组织和 Client ID，限定更新列，回读确认 Client ID / Secret 不变。该证据不自动扩展到其他字段、生产权限或完整授权语义。

Mayfly 自身接口须明确携带 serviceId 和组织引用，例如组织目录、应用、用户、授权、操作列表及变更预览。凭证仅通过受控 credentialId 在服务端选择，不作为目录身份，也不能由请求随意覆盖。具体 URL、DTO 和仓储接口在新版实施计划中定义，不继续沿用含义混杂的 connectionId。

## 10. 历史数据迁移

迁移分为只读盘点、候选生成、管理员确认、可重跑执行和引用验收。迁移仅修改 Mayfly 本地数据，不创建 Casdoor 用户、应用、密钥、角色或权限。

对 `casdoor-octop-8090` 的处理要求：

1. 保留原记录 ID、名称、配置、密文和审计，登记为历史集成配置，不直接重命名成全局管理服务。
2. 原 serverUrl 用于生成服务候选；发现多个历史行同地址时列为可合并候选，需确认实际部署身份后才合并。
3. 原 `smartcore` 生成组织候选，验证后建立 service + organization 引用；不因原配置存在就宣称能列举全部组织。
4. 原 Client ID / Secret 保留作历史应用认证配置。来源应用通过源端可读资料验证，不能仅依据历史名称认定属于 8090，也不能自动升级为管理整套服务的身份。新的专用管理身份须另行明确配置。
5. 原 `appOwner=octop` 保留作历史诊断信息，不迁移成新服务的组织目录过滤条件，不自动修改 Casdoor Owner。
6. 快照通过映射表关联新服务与组织，保留稳定源 ID和既有业务引用；无法确定归属的记录进入待确认区，不丢弃或强行合并。
7. 迁移到一个组织的多个历史快照只能按已验证源身份去重，禁止按名称或邮箱合并。冲突生成清单并阻止受影响范围切换。
8. 现有应用/Octop/身份关联通过 ID 映射保持，允许同一应用对应多个业务部署。旧普通账号的操作权限不能因服务身份升级而自动扩大；无法无损映射的权限进入确认清单。

新旧调度器不能同时写同一逻辑目录。切换前完成映射、备份和验收，切换后旧表只作历史恢复依据。回退须恢复与引用映射一致的应用版本和数据；不能直接回旧镜像读取过期旧表。凭证轮换后恢复方案不得重新启用已撤销凭证。

迁移使用实施时 `server/internal/pkg/config/app.go` 的当前 Version；只追加对应批次迁移，已发布迁移的 ID、顺序和定义不修改，每条新增迁移幂等。

## 11. 非功能要求

所有展示文本中英文国际化；页面区分无权限、未选择组织、未同步、查询无匹配、真实空目录和采集失败。时间显示按系统时区，现场验收使用 Asia/Shanghai。错误输出使用稳定原因码，不暴露令牌、应用密钥或源端完整敏感响应。

列表服务端分页、默认每页 10 条，选择器支持分页搜索；不得固定取 200 条冒充全部。1024px 与 1440px 下布局可用，慢请求、切换上下文、重复点击及刷新操作结果均有明确状态。

服务地址须验证协议和目标，敏感凭证服务端加密保存，令牌过期可检测且可轮换。前端只能看到凭证已配置及脱敏身份信息，不显示或导出密钥。

核心代码仍独立于 Octop，沿用仓库分层、API 封装及迁移规则。发布前完成模块测试、权限与失败场景测试、同版本隔离写契约测试、前端构建及实际启动后的 API 和页面验证。

## 12. 验收标准

- AC-01：登记一套 Casdoor 服务，仅出现一个服务行；添加第二个组织或更换管理身份不增加服务行。
- AC-02：服务连接使用专用管理应用凭证自动换取 Bearer 令牌，可发现包括内置组织的组织列表；不复用 Octop 业务应用身份、不依赖人工定期粘贴令牌、不触发 Mayfly 单点登录配置。
- AC-03：应用凭证兼容方式明确显示来源与范围；不能被标为全局权限，不能形成应用包含其他应用或组件的层级。
- AC-04：只能管理单个业务组织的身份不能通过全服务管理连接验收；请求跨服务对象、伪造目标或无管理动作权限时必须被拒绝。
- AC-05：组织列举被拒绝时展示连接验证失败，不显示“服务没有组织”或伪造全量组织数，不以手工登记单组织冒充完整连接。
- AC-06：同一组织中的多个应用和用户分别列出；用户不随应用数重复，应用不因未关联 Octop 而被过滤。
- AC-07：组织应用目录不携带历史业务 Owner 筛选；应用真实 Owner 与 organization 分别保存。
- AC-08：凭证轮换保持目录与业务引用，旧预览失效；低权限凭证不能回退到高权限身份重试。
- AC-09：多组织同步独立提交；分页失败、重复页或受限结果不能清空旧快照或标记源对象删除。
- AC-10：只读身份可查看允许目录，写入入口受范围和动作双重控制；无可靠激活路径时禁用新建用户并说明原因。
- AC-11：预览零远端写入，执行重复提交不重复修改；源漂移、过期、未知结果及部分成功按原要求显示和核对。
- AC-12：授权结果区分组织归属、受管角色成员、有效策略和业务会话；无法解释策略时不声称已授权或已彻底封禁。
- AC-13：同一业务系统的 Casdoor 应用可关联多个 Octop 部署实例，不引入实例级访问授权模型；关联不改变 Casdoor 原生对象定义。
- AC-14：历史配置迁移前后组织用户数量、源稳定 ID、应用引用和身份关联可核对；重跑无重复，无权限扩大，无远端写入。
- AC-15：五个页面及所需 API 在实际启动环境中验证，无 404；成功返回需要业务成功和真实数据核对，不能只看菜单、HTTP 200 或组件存在。
- AC-16：新菜单、路由、翻译和服务注册随可用功能一起发布；未完成动作明确禁用，不将页面初版或构建通过视为完整交付。
